---
title: MCP server for coding agents
description: Connect coding agents to Portcn's read-only local listener and availability tools.
---

The published `v0.6.0` package includes a local Model Context Protocol server for coding agents. It uses stdio and exposes bounded read-only queries. On Linux, listener and process evidence is scoped to visible namespaces. The limited macOS listener adapter uses the current host view and does not provide Linux `/proc` process details. It does not run a model, require an API key, open an HTTP server, or provide process-control tools.

## Start the server

The published `portcn` executable must be on `PATH`:

```json
{
  "mcpServers": {
    "portcn": {
      "command": "portcn",
      "args": ["mcp"]
    }
  }
}
```

For a source checkout, build the workspace and set the command to `node` with arguments `/absolute/path/to/portcn/apps/cli/dist/index.js` and `mcp`.

## Available tools

| Tool | Purpose | Bounds |
| --- | --- | --- |
| `list_listeners` | List visible TCP/UDP listeners with owner PID and process name when available. | Maximum 100 results; optional protocol filter. |
| `diagnose_port` | Report listener owners, namespace limits, and selected Git project evidence. | One port; up to 100 listeners and 20 owners per listener. |
| `check_port_availability` | Check observed overlap for one protocol and bind address. | One port and a local IP address. |
| `suggest_ports` | Return candidates with no observed overlap. | Maximum range 1024 ports and 20 suggestions. |
| `discovery_snapshot` (Linux) | Return a bounded unified discovery relationship summary. | Same coordinator as `portcn discover snapshot`; optional full provider payload; default 100 edges. |

Tool schemas are advertised through MCP and invalid arguments are rejected before execution. Linux discovery uses `ss`; macOS listener discovery uses `lsof`. Both use a 10-second process timeout. Tool failures return structured MCP errors; stdio stdout is reserved for protocol messages.

## Read results carefully

<Callout title="A snapshot is not a reservation" type="warn">
An available result means Portcn observed no conflicting listener at that moment. It does not bind or reserve the port, and another process may claim it immediately.
</Callout>

Portcn only sees sockets visible to its current Linux namespace or macOS host view. Process/project evidence may be incomplete because of permissions, process exits, or Linux PID namespace boundaries; macOS process command lines, user IDs, project context, and agent markers are unavailable. Project checkout details on Linux describe the current filesystem, not necessarily the code loaded by a running process. MCP diagnosis deliberately omits command lines, user identifiers, agent labels, session identifiers, and environment values.

The MCP server and its read-only tools are available in the published package. Linux hosts also receive `discovery_snapshot` for relationship summaries without replacing per-command JSON. The reusable [Portcn agent skill](https://github.com/jayantrohila57/portcn/tree/main/.agents/skills/portcn-agent) provides usage guidance for coding agents.
