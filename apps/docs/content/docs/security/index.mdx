## Current execution behavior

The Linux CLI reads listening sockets from the current network namespace through `ss` and may read visible process metadata from `/proc`. The `diagnose` command uses an owner process's working directory and up to five ancestors to query Git for project/worktree metadata. With opt-in `PORTCN_AGENT_SESSION_ID` and optional `PORTCN_AGENT_NAME` markers, it inspects owner and ancestor environment files to extract only those exact keys; it does not retain or emit other environment values, agent conversations, or prompt data. These reads are bounded, read-only, and may be incomplete due to permissions, process exits, namespaces, or missing Git metadata. The output includes visible filesystem paths and executable locations. Agent markers are user-supplied evidence, not authenticated identities; possible leftover status is not evidence that a process is safe to stop. The CLI does not elevate privileges, change sockets, or terminate processes. It does not inspect host or other network namespaces automatically. The Docker test workflow mounts Git metadata read-only and does not expose the Docker socket.
