The [SECURITY.md policy](https://github.com/jayantrohila57/portcn/blob/main/SECURITY.md) is the canonical vulnerability reporting process. Do not report vulnerabilities in public issues; use GitHub's private vulnerability reporting when available.

## Current execution behavior

The Linux CLI reads listening sockets from the current network namespace through `ss` and may read visible process metadata from `/proc`. The `diagnose` command uses an owner process's working directory and up to five ancestors to query Git for project/worktree metadata. With opt-in `PORTCN_AGENT_SESSION_ID` and optional `PORTCN_AGENT_NAME` markers, it inspects owner and ancestor environment files to extract only those exact keys; it does not retain or emit other environment values, agent conversations, or prompt data. `assess <pid>` compares visible project/session evidence and checks PID start time before and after collection; it remains limited to the current PID namespace and permissions. `verify <endpoint>` reads TCP listener and current checkout metadata only; it does not connect, issue HTTP requests, check TLS, or prove which code a process loaded. These reads are bounded, read-only, and may be incomplete due to permissions, process exits, namespaces, or missing Git metadata. The output includes visible filesystem paths and executable locations. Agent markers are user-supplied evidence, not authenticated identities; possible leftover status is not evidence that a process is safe to stop. The CLI does not elevate privileges, change sockets, or terminate processes. It does not inspect host or other network namespaces automatically. The Docker test workflow mounts Git metadata read-only and does not expose the Docker socket.

The development ``config`` commands store only user-authored service identities, favorites, aliases, notes, and group names in the user's XDG config directory. The directory is restricted to owner access and the JSON file to mode ``0600``. Listener status is recomputed at read time; process metadata and discovery results are not saved. A validated previous config is retained as a local backup for recovery.

<Callout title="Report privately" type="warn">
Include a clear impact and reproduction steps in a private report. Do not include credentials, tokens, or unrelated personal data.
</Callout>
