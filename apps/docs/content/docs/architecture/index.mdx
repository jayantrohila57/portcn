- `apps/cli` owns the executable, command parsing, and user-facing output.
- `apps/docs` owns the independent Fumadocs website and its content.
- `packages/core` contains reusable, platform-independent domain logic.

## Dependency boundaries

Applications can depend on workspace packages. Packages must not depend on apps. Core must not import CLI presentation, operating-system process inspection, or Linux APIs. These boundaries are checked by `pnpm boundaries:check`.

## Current CLI flow

The executable entry point creates a Commander root program, sets its package version, and parses arguments only when invoked as the process entry point. In an interactive terminal, invoking `portcn` opens the keyboard-first listener dashboard; non-interactive invocation remains help-oriented and machine-safe. Explicit `list`, `inspect`, and `diagnose` commands share the same read-only Linux socket discovery; diagnosis adds process and namespace explanations in the CLI app.

## Terminal dashboard implementation

The dashboard uses a shared terminal lifecycle, full redraw, resize-aware layout, pagination, selection, search, sorting, a command palette, process details, scheduled refresh, Unicode-aware widths, and responsive columns. These behaviors are covered by focused CLI tests and the real-PTY matrix below.

The UI acceptance checklist for each slice is: no layout shift across tabs/pages, no clipped or wrapped table borders, correct page totals and visible ranges, matching row highlight and details, selection clamped to the filtered results after view changes, restored cursor/raw mode on exit, graceful behavior for small or non-interactive terminals, and unchanged plain-text/JSON command output. `list --json` and `inspect --json` bypass the screen renderer and always return complete machine-readable results.

The current implementation intentionally uses a small in-house renderer over Node's terminal APIs. A framework such as Ink or blessed would add a dependency and a second rendering model before Portcn has a component tree or event abstraction; the existing renderer already supports deterministic output, raw-mode cleanup, and focused Vitest coverage. We will reassess that choice when selection, search, dialogs, and asynchronous refresh require shared stateful components.

The current interaction map includes `/` to search, `Enter` to finish a query or open selected details, `Esc` to cancel it, `j`/`k` or arrow keys to select rows, `s` to cycle port/protocol/process sorting, and `:` for refresh/auto-refresh commands. Refresh keeps the current view state and retains the last good snapshot when discovery fails. The renderer sanitizes control characters, accounts for wide Unicode glyphs, and hides lower-priority columns on narrow terminals.

The real-PTY matrix is run after the CLI build with `node --test scripts/dashboard-pty.test.mjs`; it starts the interactive command in `script` at 40x12, 80x24, and 140x40, sends a delayed quit key, verifies cursor restoration, sends Ctrl+C in raw mode and verifies exit status 130, and types a Unicode search query in a narrow terminal. Rendering failures restore raw mode and cursor before the command reports the error.
