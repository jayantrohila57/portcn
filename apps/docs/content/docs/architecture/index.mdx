- `apps/cli` owns the executable, command parsing, and user-facing output.
- `apps/docs` owns the independent Fumadocs website and its content.
- `packages/core` contains reusable, platform-independent domain logic.

## Dependency boundaries

Applications can depend on workspace packages. Packages must not depend on apps. Core must not import CLI presentation, operating-system process inspection, or Linux APIs. These boundaries are checked by `pnpm boundaries:check`.

## Current CLI flow

The executable entry point creates a Commander root program, registers command modules, sets its package version, and parses arguments only when invoked as the process entry point. In an interactive terminal, invoking `portcn` opens the keyboard-first listener dashboard; non-interactive invocation prints help. Linux discovery uses `ss` and Linux process details use bounded `/proc` reads. The limited macOS adapter uses `lsof` for `list`, `inspect`, and `diagnose`; it does not provide Linux process, project, or agent-marker fields.

## Implemented command modules

| Module | Current responsibility |
| --- | --- |
| `list`, `inspect`, `diagnose` | Read-only native listener discovery, port details, process/project evidence, and visibility limits. |
| `availability` | Point-in-time overlap checks, bounded suggestions, and cancellable port wait. |
| `project-context`, `agent-attribution`, `process-assessment`, `endpoint-verification` | Linux project/session evidence with PID reuse checks and conservative results. |
| `config-store`, `config`, `endpoints` | Versioned local saved-service data, local URL candidates, explicit probes, and browser open. |
| `readiness`, `connection` | Bounded local readiness and staged connectivity diagnostics. |
| `docker`, `podman`, `nginx`, `systemd`, `exposure` | Optional read-only runtime inventories, Podman rootlessport attribution, Nginx configuration evidence, visible user/system systemd units, and bind-scope classification. |
| `mcp` | Bounded, read-only stdio tools for visible listeners, diagnosis, availability, and suggestions. |

These modules are implemented in `apps/cli`; `@portcn/core` exports platform-independent identities, evidence and result contracts, scope-safe duplicate reconciliation, and container-mapping correlation. Operating-system discovery and terminal presentation stay out of the platform-independent package.

Linux provider adapters in `apps/cli` still expose their original command-level JSON contracts. Native sockets, Docker, Podman, Nginx configuration, and systemd units additionally feed a shared `DiscoverySnapshot` model in `@portcn/core`: versioned identities, evidence, provider results, and evidence-backed service relationships with nature, freshness, and confidence. `portcn discover snapshot` and the Linux MCP `discovery_snapshot` tool read the same coordinator as the relationship engine; existing per-command outputs remain unchanged. Safe Docker/Podman reconciliation, advisory `rootlessport` attribution, and systemd MainPID-only process links stay scoped by caller permissions and namespaces. On Linux, the interactive dashboard presents a source-aware service view for native listeners, Docker, Podman, Nginx, and systemd (#187). Do not treat configured mappings or an Nginx/systemd declaration as proof of an active listener.

Issue #180 defines the platform-neutral contracts for identity, provider results, evidence, freshness, namespace scope, partial results, and correlation. See [Unified service discovery contracts](./unified-service-discovery) for the audited data flow and compatibility boundaries. Existing Docker/Podman command outputs remain unchanged while providers are migrated incrementally.

## Terminal dashboard implementation

The dashboard uses a shared terminal lifecycle, full redraw, resize-aware layout, pagination, selection, search, sorting, a command palette, live bind/process/project details for the selected listener, scheduled refresh, grapheme-aware cell widths, and responsive columns. Selection includes a text marker so it remains visible without color. The semantic terminal palette respects `NO_COLOR` and `TERM=dumb`. These behaviors are covered by focused CLI tests and the real-PTY matrix below.

The UI acceptance checklist for each slice is: no layout shift across tabs/pages, no clipped or wrapped table borders, correct page totals and visible ranges, matching row highlight and details, selection clamped to the filtered results after view changes, restored cursor/raw mode on exit, graceful behavior for small or non-interactive terminals, and unchanged plain-text/JSON command output. `list --json` and `inspect --json` bypass the screen renderer and always return complete machine-readable results.

The current implementation intentionally uses a small in-house renderer over Node's terminal APIs. A framework such as Ink or blessed would add a dependency and a second rendering model before Portcn has a component tree or event abstraction; the existing renderer already supports deterministic output, raw-mode cleanup, and focused Vitest coverage. `@clack/prompts` is not added because saved service configuration currently uses explicit CLI arguments and does not need a guided setup flow. Reassess it only if a guided setup or confirmation task appears; Clack is not a persistent dashboard renderer.

The current interaction map includes `/` to search, `Enter` to finish a query, `Esc` to cancel it, `j`/`k` or arrow keys to select rows, `s` to cycle port/protocol/process sorting, and `:` for refresh/auto-refresh commands. Bind, process owner, and best-effort project evidence update with the selected listener; context explains status and confidence and does not prove which code a running process loaded. Refresh preserves the selected listener when it remains visible and retains the last good snapshot when discovery fails. The renderer sanitizes control characters, measures grapheme and wide-cell text, and hides lower-priority columns on narrow terminals.

The canonical layout, component, keyboard, color, accessibility, and dependency rules are in the [terminal design system](../development/terminal-design). The real-PTY matrix is run after the CLI build with `node --test scripts/dashboard-pty.test.mjs`; it starts the interactive command in `script` at 40x12, 80x24, and 140x40, sends a delayed quit key, verifies cursor restoration, sends Ctrl+C in raw mode and verifies exit status 130, types a Unicode search query in a narrow terminal, and checks monochrome selection. Rendering failures restore raw mode and cursor before the command reports the error.
