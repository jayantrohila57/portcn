The repository's [CHANGELOG.md](https://github.com/jayantrohila57/portcn/blob/main/CHANGELOG.md) records pending work in an Unreleased section. Release Please owns official versioned notes and product versions. Automated maintenance and release reconciliation of the pending section are not yet implemented.

## Release flow

1. Task PRs merge to `dev` with Conventional Commit titles.
2. After approximately three to five validated tasks, prepare a promotion PR; an authorized merge moves `dev` to `main` while preserving task commits.
3. Release Please runs on `main`, calculates the version, and opens the release PR. It updates the CLI and root package versions, manifest, changelog, and release metadata.
4. After an authorized release PR merge, synchronize `main` back to `dev` through the approved sync PR.

Before `1.0.0`, features and breaking changes advance the minor version; fixes advance the patch version. Release Please owns version edits and tag/release creation. Do not publish or deploy without authorization.

The [Contributing guide](https://github.com/jayantrohila57/portcn/blob/main/CONTRIBUTING.md) contains the full promotion procedure.

A proposed version and pending release summary must reflect actual release-relevant commits and configured path exclusions. Release Please makes the authoritative calculation after promotion; a preview is not an official version. Merging the promotion or release PR, tagging, publishing, and public releases require explicit authorization.

## Proposed first release

The proposed `v0.0.1` baseline is main commit `846b45801d808bd728161ccc0e3bf4941c5d6756`, which passed the main CI build and package checks. It contains branded CLI help and version output, not port discovery or service management. No tag or GitHub Release exists yet. Verify the exact package version output and obtain explicit approval before creating the annotated tag or GitHub Release.

The CLI package first appeared at `7b00ee09a51bdc5c7b3969dad837940b4469efd5`; the later main commit is proposed because it has validated integration and release configuration. The baseline and pending sections in the changelog remain proposals until release reconciliation is implemented.

Run `node scripts/release-preview.mjs` to inspect a provisional calculation from the current manifest and `origin/dev`. Fetch `origin/dev` first. Until `v0.0.1` exists, the command uses the proposed baseline; once a manifest version has a matching tag, it uses that tag. For `v0.0.1`, the preview rejects a tag pointing to a different commit. The preview follows the target branch first-parent history, including merge commits; it is not Release Please and does not create releases or update the changelog.

For a task, run `node scripts/task-lifecycle.mjs changelog "feat(cli): describe the change"` before committing to add an idempotent Unreleased entry. CI and task submission require the matching entry; release reconciliation remains unfinished; do not treat this as a completed release process.

Release Please uses the proposed baseline as its `bootstrap-sha` to exclude earlier commits from the first generated release PR. This setting does not create the initial tag or release and does not prove that GitHub has recognized them.

After `task-lifecycle.mjs finish`, the helper runs `node scripts/prepare-promotion.mjs`. It checks merged task PRs since `main` and creates or updates a `dev` to `main` PR after three tasks. The PR contains the current Unreleased text and a provisional version; review its scope and CI before approving any merge. If preparation fails, local cleanup has already completed; retry the preparation command on `dev`.

Release PR validation rejects an Unreleased section containing entries and requires a matching version section. Release Please reconciliation is not yet automated, so this check can block a release PR until the notes are reconciled.

The changelog policy includes a tested reconciliation function that refuses to clear an entry unless the versioned notes contain an exact matching bullet; unsupported prose or list formats stop reconciliation. It is not yet connected to the Release Please workflow.
