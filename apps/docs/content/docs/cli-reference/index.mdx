The Linux CLI provides read-only ``portcn list``, ``portcn inspect``, and ``portcn diagnose`` commands. Published ``v0.2.0`` includes ``list`` and ``inspect``; ``diagnose`` is available from the development branch and will ship in a later package release.

```sh
node apps/cli/dist/index.js --help
node apps/cli/dist/index.js list
```

For an interactive view, use ``--interactive``. The view is divided into an ASCII title header, a tab navigation row, the full-width table, and a footer with the controls. Press ``1`` for all listeners, ``2`` for TCP, ``3`` for UDP, ``4`` for listeners with visible processes, ``Tab`` for the next tab, ``n`` or Space for the next page, ``p`` for the previous page, and ``q`` or ``Esc`` to quit. Interactive mode requires a terminal; piped output remains the normal table.

```sh
node apps/cli/dist/index.js list --interactive
node apps/cli/dist/index.js list --json
node apps/cli/dist/index.js inspect 3000 --json
node apps/cli/dist/index.js diagnose 3000 --json
```

The `--json` forms always emit the complete result set without pagination, colors, or screen-control sequences.

## ``portcn list``

Lists listening TCP and UDP sockets on Linux. Requires ``ss`` (provided by ``iproute2`` on Ubuntu). This command runs ``ss --no-header --listening --tcp --udp --numeric --processes`` without using a shell. It does not change ports, processes, or services.

```sh
node apps/cli/dist/index.js list
```

Output is rendered as an ASCII table with colored headers and protocol/state values in an interactive terminal. Colors are automatically omitted when output is piped. Columns are ``PROTO`` (TCP/UDP), ``STATE``, ``PORT`` (numeric), ``LOCAL ADDRESS`` (bind address), ``PID`` and ``PROCESS``. Results are sorted by ascending port number. PID and process may display `` - `` when the operating system does not expose ownership to your current user. You do not need to run with sudo just to list visible sockets.

Example with sample data from tests:

```text
PROTO  STATE   PORT  LOCAL ADDRESS  PID  PROCESS
TCP    LISTEN  22    [::]           12   sshd
TCP    LISTEN  3000  127.0.0.1      321  node
UDP    UNCONN  5353  0.0.0.0        -    -
```

If no listening sockets are found, Portcn prints ``No listening TCP or UDP ports found.``

## ``portcn inspect <port>``

The `inspect` subcommand inspects all visible TCP and UDP listeners for one port using the same read-only Linux discovery path as ``list``. It prints a bordered ASCII table with protocol, socket state, local address, PID, process name, and best-effort ``/proc`` command details. IPv4, IPv6, and multiple listeners are retained. A missing listener is informational and returns status 0; an invalid port returns status 2. Interactive terminals receive color; piped output stays plain.

```sh
node apps/cli/dist/index.js inspect 3000
```

The command never changes sockets or processes and does not require sudo. Process details may show ``unavailable`` when ``/proc`` access is restricted. Linux and ``ss``/``iproute2`` limitations are the same as ``list``.

## ``portcn diagnose <port>``

Diagnoses every TCP or UDP listening socket visible on the requested port. It reuses the read-only ``ss`` discovery used by ``list`` and ``inspect`` and reports each bind address, IPv4/IPv6 family, socket state, and every PID/process owner shown by ``ss``. For each visible PID it adds the best-effort command and user from ``/proc``. Shared sockets with multiple visible PIDs appear once in JSON with an ``owners`` array and as one row per owner in terminal output.

```sh
node apps/cli/dist/index.js diagnose 3000
node apps/cli/dist/index.js diagnose 3000 --json
```

The JSON result has ``schemaVersion``, ``port``, ``namespace``, ``listeners``, ``messages``, and ``limitations`` fields. Each listener includes ``protocol``, ``state``, ``bindAddress``, ``addressFamily``, and ``owners``. Owner fields include ``pid``, ``processName``, ``command``, ``user``, and ``detailsStatus`` (``available``, ``permission-denied``, ``process-exited``, or ``unavailable``). When no process ID is visible, the listener's ``owners`` array is empty and the messages explain that permissions or namespace boundaries can hide ownership.

The result identifies the current network and PID namespace. It does not inspect the host or other namespaces, elevate privileges, change processes, or reserve a port. A no-listener result is a point-in-time observation, not a guarantee that a later bind will succeed. Compare protocol, address, and IPv4/IPv6 behavior with the server you plan to start.

| Exit status | Meaning |
| --- | --- |
| ``0`` | Diagnosis completed, including when no listeners are visible. |
| ``1`` | Discovery failed, the platform is unsupported, or ``ss`` is unavailable. |
| ``2`` | The port is not an integer from 1 through 65535. |

With ``--json``, invalid arguments and discovery failures are emitted on stdout as ``{"error":{"code":"INVALID_PORT"|"DIAGNOSIS_FAILED","message":"...","port":"..."}}``. Terminal mode writes failures to stderr.

## Errors and limitations

- Supported platform: Linux only. On other platforms, discovery commands print ``Port listing currently supports Linux only.`` and exit with status 1.
- If ``ss`` is missing, install ``iproute2`` (Ubuntu: ``sudo apt install iproute2``). Portcn exits with status 1 instead of hiding the error.
- Failures or unexpected output from ``ss`` produce a nonzero exit and explanatory error. Hidden process metadata appears as `` - `` rather than an invented owner.
- Containers only see sockets in the current network namespace unless explicitly configured otherwise. ``diagnose`` shows the current namespace identifiers and does not inspect host namespaces automatically.
- ``list``, ``inspect``, and ``diagnose`` provide JSON output. Portcn does not kill processes or provide process/service management commands.

## Help and version

Running Portcn without arguments opens the dashboard in an interactive terminal and displays branded help when output is non-interactive. ``--help`` always displays help, while ``--version`` prints the package version. These paths return status 0.

```sh
node apps/cli/dist/index.js
node apps/cli/dist/index.js --help
node apps/cli/dist/index.js --version
```

Running `portcn` without a subcommand in an interactive terminal opens the listener dashboard. The dashboard uses the same tabbed, paginated view as `portcn list --interactive`; use `/` to search, `j`/`k` or arrow keys to select, `Enter` for process details, `s` to cycle sorting, and `:` for the command palette (`r` refreshes, `a` toggles five-second auto-refresh). Narrow terminals hide lower-priority columns rather than wrapping borders. In a non-interactive terminal, the command prints help instead.

See [Getting Started](/docs/getting-started) for local development.
